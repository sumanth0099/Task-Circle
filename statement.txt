

# Build TaskCircle — Production-Ready Full-Stack Application

Build the complete **TaskCircle** application as a production-ready full-stack web application.

The project must be **fully runnable locally, Dockerized, and ready to deploy directly to Render** for both the frontend and backend.

Do not provide only examples, pseudo-code, incomplete files, or architecture descriptions. Generate the actual implementation with all required files, configurations, database migrations, Dockerfiles, environment examples, README documentation, and deployment configuration.

---

# 1. Core Requirements

TaskCircle is a collaborative task-management platform based around **Circles**.

Users can:

* Sign in using Google
* Create Circles
* Join Circles
* Manage Circle members
* Assign tasks
* Assign a task to every Circle member
* Track task progress
* Receive notifications
* Receive automated deadline reminders
* Manage their profile and notification preferences

The application must be designed as a real production application rather than a classroom prototype.

# 4. Authentication

Completely remove:

* Email/password login
* Password registration
* OTP
* 6-digit OTP
* Password reset
* JWT
* localStorage authentication tokens

Use **Google OAuth only**.

Authentication flow:

```text
User
 ↓
Continue with Google
 ↓
Google OAuth
 ↓
Backend receives OAuth callback
 ↓
Backend verifies Google identity
 ↓
Find user by Google ID/email
 ↓
Create user if necessary
 ↓
Create server-side session
 ↓
Store session in Redis
 ↓
Set secure HTTP-only cookie
 ↓
Redirect to frontend
```

Use:

```text
express-session
```

with a Redis-backed session store.

The browser must never receive a JWT.

Do not store authentication tokens in:

```text
localStorage
sessionStorage
```

Use secure HTTP-only cookies.

Production cookie configuration must properly support Render deployment.

Use environment-based configuration for:

* `secure`
* `sameSite`
* session secret
* frontend URL

# 6. PostgreSQL

# 15. Assign to All

Implement a real **Assign to All** feature.

When an authorized user chooses:

```text
Assign to All
```

the backend must:

1. Retrieve all active Circle members.
2. Create an independent task for every member.
3. Assign each task to one member.
4. Create a NEW_TASK notification for each assignee.

Do NOT create one shared task record.

Example:

```text
Circle has 5 members

Assign to All
        ↓
5 independent task records
        ↓
Member A → Task
Member B → Task
Member C → Task
Member D → Task
Member E → Task
```

Each user must be able to update their own task independently.

Use a database transaction where appropriate so bulk assignment does not leave partially-created data.


```text

```

The scheduler should:

1. Find incomplete tasks.
2. Identify tasks due today.
3. Identify tasks due tomorrow.
4. Identify overdue tasks.
5. Check user notification preferences.
6. Prevent duplicate notifications where appropriate.
7. Insert notifications into PostgreSQL.

Do not create duplicate notifications every time the scheduler executes.

The scheduler must work correctly in the Render backend service.

Document the scheduler in the README.
